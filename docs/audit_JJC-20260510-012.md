## 四、🐛 代码 Bug 排查

### Bug #1 — ⚠️ 中等严重: `_update_symbols_pool` 参数传递错误

**文件**: `core/engine.py` L1196
```python
env_flag = "--prod" if BINANCE_API_ENV == "prod" else "--testnet"
```

**脚本实际支持的参数** (`scripts/update_symbols_pool.py` L397-398):
```python
parser.add_argument("--dry-run", action="store_true")
parser.add_argument("--no-prod", action="store_true")
```

**问题**: 引擎传递 `--prod` 或 `--testnet`，但脚本只接受 `--dry-run` 和 `--no-prod`。传递未知参数会导致 argparse 报错退出。

**影响**: 引擎的每日自动品种池更新功能（L1597-1607）**实际上永远不会成功执行**。这是一个死功能。

**严重性**: 🔶 中等 — 当前在 testnet 模式下传递 `--testnet` 会报错，但这反而是一个"安全失败"（不会意外触发生产操作）。不过功能完全不可用。

**修复建议**:
```python
# 方案1: 修改引擎传参
env_flag = "--no-prod" if BINANCE_API_ENV != "prod" else ""

# 方案2: 修改脚本支持 --prod/--testnet 参数
parser.add_argument("--prod", action="store_true")
parser.add_argument("--testnet", action="store_true")
```

### Bug #2 — ℹ️ 低严重: `highest_pnl` 初始化不一致

**文件**: `core/engine.py` L393 和 L918

```python
# Position dataclass 默认值
highest_pnl: float = -999   # L393

# DRY-RUN 开仓时
highest_pnl=0,               # L918
```

**问题**: dataclass 默认 `-999` 但 DRY-RUN 开仓传 `0`。实盘开仓（L950+）不设置此字段，依赖 dataclass 默认值。

**影响**: DRY-RUN 模式下追踪止损需要等待盈利超过 0% 才激活（因为 `highest_pnl=0`），而实盘模式下需要盈利超过 `-999%`（实际上第一个正盈利就会触发）。行为不一致，但**不影响安全性**。

**严重性**: 🟢 低 — 不影响安全性，DRY-RUN 行为略有不同

---

### Bug #3 — ℹ️ 低严重: backtest.py `_open_position` 仓位计算方式与引擎不同

**文件**: `core/backtest.py` L215
```python
position_value = self.equity * self.risk_cfg["position_size_pct"] / 100
```

**引擎** (`core/engine.py` L882):
```python
fixed_margin = self.cfg.get("fixed_margin_usdt", 50)
nominal = fixed_margin * leverage
```

**问题**: 回测引擎使用 `equity × position_size_pct` 计算仓位，而实盘/模拟引擎使用固定 50U 保证金。回测结果与实盘表现会有偏差。

**影响**: 回测不能准确反映 50U 固定保证金策略的实际表现。

**严重性**: 🟢 低 — 仅影响回测准确性，不影响交易安全

## 七、⚠️ 风险提示

1. **测试网 API Key 为空**: `secrets/api_keys.env` 中 `BINANCE_TESTNET_API_KEY` 和 `BINANCE_TESTNET_SECRET_KEY` 为空。引擎当前以"未认证"模式运行，使用模拟账户余额（10000 USDT）。如需在 testnet 真实交易，需要填写 testnet 密钥。

2. **实盘 Key 已写入**: `secrets/api_keys.env` 包含实盘 API Key。虽然当前隔离安全，但**如果未来有人将 `BINANCE_API_ENV` 改为 `prod`**，引擎将直接使用实盘 Key 交易。建议在切换到实盘前增加额外的确认机制。

3. **517 品种全部启用**: 引擎每个周期会对 517 个品种分别请求 2m 和 15m K 线，共 1034 次 HTTP 请求。建议按策略需要只启用少量品种（如 10-30 个）。

4. **每日品种池自动更新损坏**: 因 Bug #1，引擎的自动品种池更新功能不可用。需要手动运行 `python3 scripts/update_symbols_pool.py` 来更新。
